M13 awl.ui implementation plan¶

For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

Goal: Render a workflow, let a human edit it, write the result back to source, and overlay what actually ran.

Architecture: An anywidget component, so one artefact serves the notebook, a Panel app via AnyWidgetComponent, and JupyterLite. Two variants are built and compared, because the canvas paradigm is the same decision as whether control flow is the differentiator, and it should be settled by evidence.

Tech Stack: anywidget, jedison or RJSF, Blockly or React Flow, Cytoscape.js. pytest-playwright for tests.

Contract¶
Consumes CompactDoc from M12, TraceEvent list from M11
Produces rendered UI, and edit lists routed back through M12
Depends on awl.editor, awl.trace, awl.contracts

The paradigm decision¶

Node-graph editors model dataflow. Block editors model control flow. AWL-LD's differentiator against CWL, PWD and semantikon is that it carries if and while. React Flow makes a nested loop body awkward, needing group nodes or subflow conventions; Blockly represents nested statements natively with C-shaped blocks and already ships a Python generator.

Choosing a node-graph canvas quietly pushes the model back toward the dataflow shape the ecosystem already occupies. That is a product decision, so build both and measure.

Variant Canvas Form Notes
A control-flow-first Blockly jedison No React anywhere. Native nested statements
B dataflow-first React Flow RJSF RJSF is the path of least resistance in React

Both consume the same M12 model, so the comparison isolates the paradigm rather than the plumbing.

Criteria, fixed before building so the result is not rationalised afterwards:

  1. How a nested while body reads.
  2. How a typed parameter form fits inside a node.
  3. How a trace overlay attaches to the same nodes.
  4. Bundle size under JupyterLite.

Form library: jedison over RJSF, for a principle reason¶

jedison 1.19.0 react-jsonschema-form
Runtime dependencies zero React, @rjsf/validator-ajv8 (ajv), a theme
Drafts explicit modules for 04, 06, 07, 2019-09, 2020-12 via ajv8
Conformance testing official json-schema-test-suite in devDeps ajv's
$ref own ref-parser via ajv
Widget selection x-format, inside the schema uiSchema, a separate object

The decisive argument is a principle argument. RJSF's uiSchema is a second artefact, and OO-LD exists because keeping structure and semantics in two files makes them drift. jedison's x-format lives in the schema, the same in-schema extension pattern as x-oold-*, and applyOverlay supports the layered approach when it is wanted deliberately.

Two supporting points: this project is already on that codebase (OoldEditor imports @json-editor/json-editor, and jedison's author has 601 commits on json-editor against the original author's 315), and zero dependencies matters for the JupyterLite target the HITL example names.

RJSF wins on React Flow embedding, since jedison is imperative DOM and needs a mount and unmount wrapper that survives React 18 StrictMode double-invocation.

Not yet verified: that @context and x-oold-* pass through jedison untouched. Both specifications require unknown keywords to be ignored and json-editor already handles these schemas, so the risk is low, but test it against a real OO-LD schema before committing.

Non-goals¶

  • Not the editing model. That is M12, and it is testable without a browser.
  • Not graph analysis. Cytoscape.js provides a read-only view of the RDF and trace graphs; do not make one library do both jobs.

"""Visual workflow editor, delivered as an anywidget."""

from __future__ import annotations

from pathlib import Path
from typing import Any

import anywidget
import traitlets

_STATIC = Path(__file__).parent / "static"


class WorkflowEditor(anywidget.AnyWidget):
    """Render and edit a workflow, and overlay a trace.

    One component serves the notebook, Panel via AnyWidgetComponent, and
    JupyterLite, because all three consume plain ESM.
    """

    document = traitlets.Dict().tag(sync=True)
    trace_events = traitlets.List().tag(sync=True)
    variant = traitlets.Unicode("a").tag(sync=True)

    @property
    def _esm(self) -> str:
        return (_STATIC / f"variant_{self.variant}.js").read_text(encoding="utf-8")

def test_the_graph_view_renders_the_rdf_projection():
    """A distinct surface from the canvas. Do not make one library do both."""
    from awl.ui import GraphView

    view = GraphView(triples=[
        ("py:procedure", "awl:body", "py:procedure/step0"),
        ("py:procedure/step0", "awl:callee", "py:battery.device.charge"),
    ])
    assert view.node_count == 3
    assert view.read_only is True


def test_the_trace_overlay_marks_executed_nodes():
    """F10: the overlay attaches to the same nodes the editor renders,
    joined by span. Without spans in the CompactDoc there is no join key.
    """
    from awl.ui import GraphView

    view = GraphView(triples=[("a", "awl:body", "b")])
    view.apply_trace([{"kind": "line", "span": {"file": "p.py", "startLine": 3,
                                                "startCol": 4, "endLine": 3, "endCol": 9},
                       "index": 0}])
    assert view.executed_spans == [(3, 4, 3, 9)]

Acceptance¶

  • [ ] The widget exposes document and trace_events as synced state, so tests assert on the model rather than on rendering.
  • [ ] Editing a literal changes only that span in the source file.
  • [ ] Both variants run the same playwright scenario.
  • [ ] A decision is recorded against all four criteria, and the losing variant is removed.

Known limits¶

  • Playwright in CI needs browser downloads; gate the UI tests behind a marker so the default make test stays fast.
  • JupyterLite cannot run server-side code, so anything requiring M11's tracer runs only in a full kernel. The trace overlay must degrade to "no trace available" rather than erroring.
  • Variant A has no React, so jedison is the only sensible form library there; variant B could use either. Do not let that asymmetry decide the paradigm comparison.
