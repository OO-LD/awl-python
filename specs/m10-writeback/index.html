M10 awl.writeback implementation plan¶

For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

Goal: Apply an edit made in the visual editor back to the original source file without disturbing anything the edit did not touch.

Architecture: Two tiers. Value edits patch the original text by source span, using asttokens, and are byte-exact everywhere else. Structural edits (add, delete, reorder a step) go through libcst, which attaches comments and whitespace to named slots so trivia travels with the node it belongs to.

Tech Stack: asttokens (already a dependency), libcst (the edit extra).

Contract¶
Consumes original source text plus an edit list from M12
Produces new source text
Depends on awl.contracts for source-span.schema.json. No sibling module.

Why not regenerate from the AST¶

ast.parse has no comment node at all, so ast.unparse discards every comment and all formatting. Measured on the running example:

def procedure(cycles: int) -> None:
    # ramp to 4.2 V, CC phase only                        <- gone
    while i < cycles:
        charge(ChargeParam(target_voltage=4.2,   # cell limit  <- gone
                           c_rate=0.23))                   <- reflowed to one line

For workflows authored in the editor that is irrelevant. For editing a laboratory's existing procedure files it is fatal, and those are exactly the files the retrofit path targets.

The apparent fork is false. The compact form (M9) stays the editor model; only the write-back path preserves trivia. Verified with asttokens, which is already installed: locate the target_voltage value node, ask for its span (145, 148), splice the new literal into the original text. Both comments survive and layout is untouched.

The span machinery is not new work either: M11 needs co_positions() spans to attribute trace events, and those same tuples identify the patch target. One mechanism, two consumers. It also needs no unparser, only spans plus original text, so it would work unchanged for a tree-sitter frontend.

Fidelity, stated rather than assumed¶

Operation Fidelity Mechanism
Edit a literal or parameter Lossless, byte-exact outside the span asttokens
Add, delete or reorder steps Lossless libcst
Regenerate a whole file from the graph Lossy by construction ast.unparse; comments never existed in the model

Non-goals¶

  • Not the editor model. That is M9 plus M12.
  • Not a formatter. It must not reflow, reindent or normalise quotes.

"""Apply editor changes back to source without disturbing untouched text."""

from __future__ import annotations

import ast
from typing import Any

__all__ = ["span_of", "apply_edits"]


def span_of(source: str, predicate) -> tuple[int, int]:
    """Return the character span of the first AST node satisfying *predicate*.

    Parameters
    ----------
    source : str
        The original text.
    predicate : callable
        Receives an ``ast.AST`` node, returns bool.

    Returns
    -------
    tuple of int
        ``(start, end)`` character offsets into *source*.

    Raises
    ------
    LookupError
        If no node matches, so a silent no-op edit is impossible.
    """
    import asttokens

    atok = asttokens.ASTTokens(source, parse=True)
    for node in ast.walk(atok.tree):
        if predicate(node):
            return atok.get_text_range(node)
    raise LookupError("no node matched the predicate")


def apply_edits(source: str, edits: list[dict[str, Any]]) -> str:
    """Apply non-overlapping span edits to *source*.

    Edits are applied right to left so earlier offsets stay valid.

    Parameters
    ----------
    source : str
        Original text.
    edits : list of dict
        Each has ``start``, ``end`` and ``text``.

    Returns
    -------
    str
        The patched source. Every character outside an edited span is
        byte-identical to the input.

    Raises
    ------
    ValueError
        If two edits overlap, which would make the result order-dependent.
    """
    ordered = sorted(edits, key=lambda e: e["start"])
    for earlier, later in zip(ordered, ordered[1:]):
        if earlier["end"] > later["start"]:
            raise ValueError(f"overlapping edits: {earlier} and {later}")
    out = source
    for edit in reversed(ordered):
        out = out[: edit["start"]] + edit["text"] + out[edit["end"] :]
    return out

Task 2: Refuse overlapping edits, and locate spans by predicate¶

  • [ ] Step 1: Write the tests
import ast

import pytest

from awl.writeback import apply_edits, span_of


def test_overlapping_edits_are_refused():
    """Order-dependent output is worse than an error."""
    with pytest.raises(ValueError, match="overlapping"):
        apply_edits("abcdef", [{"start": 0, "end": 3, "text": "X"}, {"start": 2, "end": 5, "text": "Y"}])


def test_a_keyword_span_covers_the_whole_pair_not_just_the_value():
    """Measured gotcha: the keyword node spans `target_voltage=4.2`.

    An editor patching a *value* must therefore target the inner node, or it
    will overwrite the parameter name too. Verified offsets: the keyword is
    (130, 148) and the constant is (145, 148).
    """
    start, end = span_of(
        SOURCE, lambda n: isinstance(n, ast.keyword) and n.arg == "target_voltage"
    )
    assert SOURCE[start:end] == "target_voltage=4.2"


def test_the_value_span_is_the_one_to_patch():
    start, end = span_of(SOURCE, lambda n: isinstance(n, ast.Constant) and n.value == 4.2)
    assert SOURCE[start:end] == "4.2"


def test_span_of_raises_when_nothing_matches():
    """A silent no-op edit would be the worst failure mode here."""
    with pytest.raises(LookupError):
        span_of(SOURCE, lambda n: False)

def insert_statement(source: str, *, into: str, code: str, leading_comment: str | None = None) -> str:
    """Append a statement to a control-structure body, preserving trivia.

    Span splicing cannot do this: it has no opinion about which comment
    belongs to which statement, so a moved node cannot carry its own.
    libcst attaches trivia to named slots and can.
    """
    import libcst as cst

    leading = [cst.EmptyLine(comment=cst.Comment(leading_comment))] if leading_comment else []
    statement = cst.SimpleStatementLine(
        body=[cst.Expr(cst.parse_expression(code))], leading_lines=leading
    )

    class _Insert(cst.CSTTransformer):
        def leave_While(self, original, updated):
            return updated.with_changes(
                body=updated.body.with_changes(body=[*updated.body.body, statement])
            )

    if into != "while":
        raise NotImplementedError(f"insertion into {into!r} is not implemented")
    return cst.parse_module(source).visit(_Insert()).code

Acceptance¶

  • [ ] A literal edit leaves every byte outside its span unchanged.
  • [ ] Overlapping edits raise rather than producing order-dependent output.
  • [ ] A span lookup that matches nothing raises rather than silently doing nothing.
  • [ ] A statement insertion preserves all pre-existing comments.
  • [ ] tests/test_writeback.py imports only awl.writeback.

Known limits, to document rather than fix¶

Both were found by extracting comments from real source with libcst, and both are model decisions rather than bugs:

  • A comment inside call arguments attaches to an inner expression node, not to the statement. A per-step comment field therefore captures statement-level comments only; expression-level trivia is preserved but not editable.
  • A section banner and a commented-out line arrive identically as leading comments of the following statement. Attachment is positional, so do not try to classify them; keep an ordered list per step and let the human decide.
