M12 awl.editor implementation plan¶

For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

Goal: The editing model, headless. What nodes may be placed, what an edit does to the document, and whether the result is still a legal workflow.

Architecture: Pure functions over CompactDoc. No browser, no rendering. Every edit returns a new document and an edit list M10 can apply to source by span, so the visual and textual representations never diverge.

Tech Stack: Python stdlib plus jsonschema.

Contract¶
Consumes CompactDoc, a workflow domain JSON Schema
Produces CompactDoc plus an edit list
Depends on awl.contracts, awl.compact

The palette has two sources, and needs both¶

Source Supplies Mechanism
The workflow domain schema which constructs and callees are legal plain JSON Schema enum constraints
The OO-LD class schemas the typed parameter form for each entry the same generator that produces forms and pydantic classes

The first alone gives a list of names. The second is what makes the claim non-obvious: a ChargeParam entry that already knows its fields, their ranges and their widgets, because Diameter.schema.json and its siblings in oold-reference-schemas carry that. Blockly needs a hand-written block definition per construct and React Flow a hand-written node component; here both fall out of schemas that already exist.

An earlier draft did only the first and described it as "derived from the OO-LD schema", which was a narrowing presented as the full claim.

Legality: plain JSON Schema, no new keywords¶

This is the part with no precedent. Blockly requires a hand-written block definition per construct; React Flow requires a hand-written node component. Here the available node types fall out of the schema that already generates forms and pydantic classes.

No new keywords. An earlier draft of this spec invented x-awl-constructs and x-awl-callees. That was wrong, for a reason worth recording so it is not reinvented: an AWL document is the AST as JSON, so ordinary JSON Schema already expresses the restriction, which is what the awl-schema README states as objective 3, "allow only a whitelist of function calls".

{
  "$defs": {
    "node": {
      "type": "object",
      "properties": {
        "_type":  {"enum": ["Module", "FunctionDef", "If", "While", "Call"]},
        "callee": {"enum": ["battery.device.charge", "battery.device.rest"]}
      }
    }
  },
  "$ref": "#/$defs/node"
}

Verified against this schema:

Document Result
{"_type": "Call", "callee": "battery.device.charge"} accepted
{"_type": "Call", "callee": "os.system"} rejected
{"_type": "ClassDef"} rejected

Two reasons the plain-schema form is strictly better than a vendor keyword:

  • Any standard validator enforces it. With x-awl-callees, only AWL-aware code would know the rule; a generic validator must ignore unknown keywords and would pass os.system. That inverts the restriction objective, turning a constraint into a hint.
  • One artefact, not two. A schema carrying both a keyword list and its own properties encodes the same constraint twice, which is the drift problem OO-LD exists to eliminate.

Edits return a patch, not just a document¶

An edit that only returned the new document would force the writer to diff two trees and guess which source range changed. Returning the span makes M10's job mechanical and keeps the round trip exact.

Non-goals¶

  • Not rendering. That is M13.
  • Not source patching. That is M10; this produces the instruction, not the result.

"""The headless editing model: palette, edits, and domain validation."""

from __future__ import annotations

import copy
from typing import Any

__all__ = ["palette", "set_literal", "validate_domain"]

# Properties whose enum constraints define what may be placed. Extending this
# is a deliberate change: each entry is a claim about what a domain profile
# is allowed to restrict.
_PALETTE_SOURCES = (("_type", "construct"), ("callee", "callee"))


def _collect_enum(node: Any, prop: str, out: list[str]) -> None:
    """Gather enum values for *prop* anywhere in the schema, including $defs."""
    if isinstance(node, list):
        for item in node:
            _collect_enum(item, prop, out)
    elif isinstance(node, dict):
        properties = node.get("properties")
        if isinstance(properties, dict) and isinstance(properties.get(prop), dict):
            values = properties[prop].get("enum")
            if isinstance(values, list):
                out.extend(values)
        for value in node.values():
            _collect_enum(value, prop, out)


def palette(schema: dict[str, Any]) -> list[dict[str, Any]]:
    """Derive the placeable node types from a workflow domain schema.

    Reads ordinary JSON Schema ``enum`` constraints. There is no AWL-specific
    keyword, so the same schema both drives the palette and is enforced by any
    standard validator.

    Parameters
    ----------
    schema : dict
        A workflow domain JSON Schema.

    Returns
    -------
    list of dict
        Each has ``name`` and ``kind``, deduplicated, in schema order. Empty
        when the schema declares no enum, which means the domain permits
        nothing rather than everything.
    """
    seen: set[tuple[str, str]] = set()
    entries: list[dict[str, Any]] = []
    for prop, kind in _PALETTE_SOURCES:
        found: list[str] = []
        _collect_enum(schema, prop, found)
        for name in found:
            if (kind, name) not in seen:
                seen.add((kind, name))
                entries.append({"name": name, "kind": kind})
    return entries

def palette(schema, type_schemas=None):
    """Derive the placeable node types.

    Parameters
    ----------
    schema : dict
        Workflow domain schema; its enums say what is legal.
    type_schemas : list of dict, optional
        OO-LD class schemas; each contributes a typed entry carrying the
        fields its form needs.
    """
    entries = _legal_entries(schema)
    for type_schema in type_schemas or []:
        entries.append({
            "name": type_schema["title"],
            "kind": "type",
            "fields": dict(type_schema.get("properties", {})),
            "declaredTypes": list(type_schema.get("x-oold-instance-rdf-type", [])),
        })
    return entries

def test_setting_a_literal_returns_both_the_document_and_the_span():
    """The fixture is a real CompactDoc, produced by M9, not hand-shaped.

    An earlier draft used an invented path that does not occur in any encoded
    document, so the addressing model was never exercised. The real shape of
    `charge(ChargeParam(target_voltage=4.2))` nests Expr, Call, args, Call,
    keywords, and the path below is measured from it.
    """
    import ast

    from ast2json import ast2json

    from awl.compact import encode

    doc = encode(ast2json(ast.parse("charge(ChargeParam(target_voltage=4.2))\n")))
    path = ["body", 0, "value", "args", 0, "keywords", 0, "value"]

    probe = doc
    for key in path:
        probe = probe[key]
    assert probe == {"c": 4.2}, "the path is real"

    new_doc, edits = set_literal(doc, path=path, value=4.1, span={"start": 35, "end": 38})

    probe = new_doc
    for key in path:
        probe = probe[key]
    assert probe == {"c": 4.1}
    assert edits == [{"start": 35, "end": 38, "text": "4.1"}]

    probe = doc
    for key in path:
        probe = probe[key]
    assert probe == {"c": 4.2}, "the input is not mutated"

def set_literal(
    doc: dict[str, Any], *, path: list[Any], value: Any, span: dict[str, int]
) -> tuple[dict[str, Any], list[dict[str, Any]]]:
    """Replace a literal, returning the new document and a source patch.

    Returning the patch is what keeps the visual and textual representations
    from diverging: M10 applies it by span rather than regenerating the file.
    """
    out = copy.deepcopy(doc)
    target = out
    for key in path[:-1]:
        target = target[key]
    target[path[-1]] = {"c": value}
    return out, [{"start": span["start"], "end": span["end"], "text": repr(value)}]

Task 2b: The other three edit operations¶

F9 requires four, not one: set a literal, add a step, delete a step, reorder. Only set_literal produces a span patch M10 can apply directly; the other three are structural, so they emit a patch M10 routes through libcst. Keep them behind one API so M13 never needs to know which tier applies.

def test_adding_a_step_returns_a_structural_patch():
    doc = {"_": "Module", "body": [{"_": "Call", "$callee": "charge", "order": 0}]}
    new_doc, edits = add_step(doc, into=["body"], node={"_": "Call", "$callee": "rest"})
    assert len(new_doc["body"]) == 2
    assert [s["order"] for s in new_doc["body"]] == [0, 1], "order is renumbered"
    assert edits[0]["kind"] == "structural", "M10 must route this through libcst"


def test_deleting_a_step_renumbers_the_rest():
    doc = {"_": "Module", "body": [
        {"_": "Call", "$callee": "charge", "order": 0},
        {"_": "Call", "$callee": "rest", "order": 1},
    ]}
    new_doc, _ = delete_step(doc, path=["body", 0])
    assert [s["order"] for s in new_doc["body"]] == [0]
    assert new_doc["body"][0]["$callee"] == "rest"


def test_reordering_updates_order_not_just_position():
    """order is the query surface. A reorder that moves list position without
    updating order would leave the RDF saying the opposite of the document.
    """
    doc = {"_": "Module", "body": [
        {"_": "Call", "$callee": "charge", "order": 0},
        {"_": "Call", "$callee": "rest", "order": 1},
    ]}
    new_doc, _ = reorder(doc, path=["body"], frm=0, to=1)
    assert [s["$callee"] for s in new_doc["body"]] == ["rest", "charge"]
    assert [s["order"] for s in new_doc["body"]] == [0, 1]

Acceptance¶

  • [ ] The palette contains exactly what the schema's enums permit, deduplicated, found through $defs nesting.
  • [ ] A schema declaring nothing yields an empty palette, not an unrestricted one.
  • [ ] An edit returns a new document plus a span patch, and does not mutate its input.
  • [ ] An edit violating the domain schema raises before reaching source.
  • [ ] tests/test_editor.py imports only awl.editor, awl.compact and awl.contracts, and needs no browser.

Known limits¶

  • Palette derivation requires the restriction to be written as enum. not, allOf and oneOf combinations are equally valid JSON Schema and equally enforced, but they are not enumerable, so a domain profile using them validates correctly while offering an empty palette. That is a documented convention for domain profiles, not a code fix: do not try to invert arbitrary schema algebra.
  • _PALETTE_SOURCES fixes which properties drive the palette. Adding one is a deliberate change, because each entry asserts something about what a domain profile may restrict.
  • Structural edits (add, delete, reorder) produce patches M10 can only apply via libcst. Keep them behind the same API so M13 never needs to know which tier applies.
