M11 awl.trace implementation plan¶

For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

Goal: Record what actually ran: along which branch, for how many iterations, with which values, attributed to the AST node responsible.

Architecture: sys.settrace with opcode tracing for expression-level position, plus an interleaved sys.setprofile to name C callees the static analysis cannot see. Both hooks are independent slots and can be active at once, which is what lets a C call be attributed to a source position.

Tech Stack: Python stdlib only. sys.monitoring is a later, optional addition on 3.12+.

Contract¶
Consumes a callable to run
Produces a list of TraceEvent (trace-event.schema.json)
Depends on awl.contracts only

Why this exists at all¶

Across the whole survey, nothing records which branch was taken. Static workflow languages omit branching; orchestrators expand it away at runtime. AiiDA has real if_/while_ control flow and still keeps it out of its provenance graph: its documentation states the branch and iteration logic itself is not a node. CWL supports 8 of the 43 Workflow Patterns Initiative control patterns.

An existing prototype lives at OpenSemanticWorld/osw-chatbot/src/osw_chatbot/tests/ast_.py. It is conceptually ahead of the field and should be moved here, with two corrections below.

Correction 1: the position-packing hack is obsolete¶

The prototype smuggles column information through f_lineno:

n.lineno = n.lineno * 1000 + n.col_offset
code = compile(a, "", "exec")

It works, and gives expression-level resolution. But PEP 657 added co_positions() in 3.11, and frame.f_trace_opcodes = True plus co_positions() indexed at f_lasti // 2 reproduces the same sequence on unmodified source. Verified on b = a + 2:

('opcode', (1, 1, 4, 5))    -> a
('opcode', (1, 1, 8, 9))    -> 2
('opcode', (1, 1, 4, 9))    -> a + 2
('opcode', (1, 1, 0, 1))    -> b
lineno packing co_positions()
Requires AST rewrite and recompile Yes No
Works on installed third-party code No Yes
Column cap 999 none
End position No Yes, full (lineno, end_lineno, col, end_col)

The third row is the unlock: the hack only ever sees code the tracer compiled itself, which is why library internals were invisible.

Correction 2: a decode bug¶

line_no = frame.f_lineno
line_no = line_no // 1000       # line_no overwritten
col_offset = line_no % 1000     # modulo of the already-divided value

col_offset always equals line_no. Confirmed by running it. Moot once correction 1 lands, but do not port the arithmetic across unexamined.

C callees are visible¶

settrace does not see them. sys.setprofile does, and yields the fully qualified name directly:

('c_call', 'numpy',    'array')
('c_call', 'math',     'sqrt')
('c_call', 'builtins', 'len')

arg.__module__ + "." + arg.__qualname__ is the FQN, which is exactly the identity M2 mints. Both hooks can be active simultaneously, verified:

('AST', 3, 4)                    <- Call node math.sqrt(2)
('C-CALL', 'math.sqrt')          <- attributed here

Limits: arg is the function object, so no argument values, and no position of its own; the position comes entirely from the interleaved trace event.

This is the runtime half of retroactive minting: setprofile names the opaque callee, and M2 attaches semantics to that name later.

sys.monitoring, deferred¶

PEP 669, Python 3.12+. Gains a BRANCH event carrying destination_offset and a unified CALL event with (code, instruction_offset, callable, arg0), which is strictly more than setprofile. Costs:

Loss Detail
No frame object Every callback is (code, instruction_offset, ...). No documented route to locals; sys._getframe() works but negates the performance win. Directly blocks locals capture
No columns on LINE LINE is func(code, line_number) alone, so co_positions() cannot be reached from it
Per-interpreter, not per-thread Stated in the PEP as a difference from settrace
Expensive reconfiguration set_events mid-run triggers de-optimization, "possibly taking hundreds of milliseconds"

Adopt it for BRANCH and CALL, not as a settrace replacement, and keep settrace for frame access. The PEP explicitly supports running both.

Non-goals¶

  • Not the plan. Static extraction is M3 to M8.
  • Not an execution environment. Which container a run used cannot be derived from Python source and is assigned on top of the graph by a human or an agent.

"""Runtime tracing: what ran, along which branch, with which values."""

from __future__ import annotations

import sys
from typing import Any, Callable

__all__ = ["trace"]


def _position(frame) -> dict[str, Any] | None:
    """Return the source span of the instruction currently executing.

    Uses co_positions() (PEP 657, Python 3.11+) rather than packing the
    column into f_lineno, so this works on code the tracer did not compile.
    """
    code = frame.f_code
    index = frame.f_lasti // 2
    positions = list(code.co_positions())
    if index >= len(positions):
        return None
    line, end_line, col, end_col = positions[index]
    if line is None:
        return None
    return {
        "file": code.co_filename,
        "startLine": line,
        "startCol": col or 0,
        "endLine": end_line or line,
        "endCol": end_col or 0,
    }


def trace(fn: Callable[[], Any], *, capture_c_calls: bool = True) -> list[dict[str, Any]]:
    """Run *fn* under instrumentation and return the events it produced.

    Parameters
    ----------
    fn : callable
        Invoked with no arguments.
    capture_c_calls : bool
        Also install a profile hook, so C callees are named. settrace alone
        cannot see them.

    Returns
    -------
    list of dict
        Each conforms to ``trace-event.schema.json``.
    """
    events: list[dict[str, Any]] = []

    def tracer(frame, event, arg=None):
        frame.f_trace_opcodes = True
        if event in ("call", "line", "opcode", "return"):
            span = _position(frame)
            if span is not None:
                events.append(
                    {"kind": "line" if event == "opcode" else event, "span": span, "index": len(events)}
                )
        return tracer

    def profiler(frame, event, arg):
        if event in ("c_call", "c_return"):
            module = getattr(arg, "__module__", "") or ""
            qualname = getattr(arg, "__qualname__", repr(arg))
            events.append(
                {"kind": event, "callee": f"{module}.{qualname}".lstrip("."), "index": len(events)}
            )

    sys.settrace(tracer)
    if capture_c_calls:
        sys.setprofile(profiler)
    try:
        fn()
    finally:
        sys.setprofile(None)
        sys.settrace(None)
    return events

def test_c_callees_are_named():
    """settrace cannot see these; setprofile can, and gives the FQN M2 mints."""
    import math

    events = trace(lambda: math.sqrt(2))
    callees = [e["callee"] for e in events if e["kind"] == "c_call"]
    assert "math.sqrt" in callees


def test_a_c_call_follows_the_span_of_its_call_site():
    """Both hooks run at once, so the interleaving carries the position."""
    import math

    def work():
        return math.sqrt(2)

    events = trace(work)
    index = next(i for i, e in enumerate(events) if e.get("callee") == "math.sqrt")
    preceding = [e for e in events[:index] if "span" in e]
    assert preceding, "a positioned event precedes the C call"

Task 3: Record the branch taken and the iteration¶

This is the part with no prior art, so it is the acceptance criterion, not a by-product. Nothing surveyed records it: static workflow languages omit branching, orchestrators expand it away, and AiiDA has real control flow while keeping branch and iteration logic out of its provenance graph.

trace-event.schema.json already has both slots (kind: "branch" and iteration, "Loop ordinal. PROV has no loop counter"). An earlier draft of this spec filled neither, and its test asserted only that a line repeated, which any loop does.

Emit a branch event when a ControlStructure is entered, carrying which arm ran, and increment iteration per pass through a loop body.

Algorithm, added during implementation. This section originally gave tests and no mechanism, which is the one place the spec was a placeholder. What was built:

The arms are not visible in the opcode stream, so they are read from the source. For each file, ast.walk collects every If, While, For and AsyncFor and reduces it to four spans: the statement itself, its test, and the envelopes of body and orelse. A while registers twice, as a branch and as a loop, because its test decides an arm and its body repeats. Files that cannot be read or parsed yield nothing, so an exec'd string degrades to spans-only rather than to invented arms.

At runtime each positioned event is a (line, col) point compared against those spans:

  • Branch. Entering a test opens a pending decision; the first event outside the test closes it, with taken set by whether that event landed in the body. Verified on if flag: with no else: the true path lands in the body, the false path lands on the following statement, and both report the same span, which is what makes them recognisably the same branch.
  • Iteration. A loop's ordinal increments on each transition from outside its body to inside. The innermost containing loop wins, and advancing a loop resets the ordinals of the loops nested in its body. Without that reset a 2x3 nest reported 0..5, which reads as a six-iteration loop that never existed.

State is held per frame, keyed by the frame's identity and dropped on return, so recursion and repeated calls each get their own ordinals. A single running total reported 0..5 for a three-pass loop called twice.

Two measured properties of the mechanism, both worth knowing before reading a report:

  • co_positions() is memoized per code object. Rebuilding the list per event makes the tracer quadratic in program length, since it fires once per instruction.
  • CPython does not trace the trace function, so every line reached from inside the callback is invisible to coverage: this module reports a low percentage however well it is tested. The span algebra is therefore also exercised directly, outside the callback.

Additionally, sys.gettrace() and sys.getprofile() are saved and restored, not cleared. Clearing them silently disables a surrounding coverage run for the rest of the process, and this project's own suite runs under pytest-cov.

def test_records_which_branch_was_taken():
    """The claim with no precedent. A repeated line number is not evidence."""
    def work(flag):
        if flag:
            return "then"
        return "else"

    taken = [e for e in trace(lambda: work(True)) if e["kind"] == "branch"]
    assert taken, "a branch event is emitted"
    assert taken[0]["taken"] is True

    not_taken = [e for e in trace(lambda: work(False)) if e["kind"] == "branch"]
    assert not_taken[0]["taken"] is False
    assert taken[0]["span"] == not_taken[0]["span"], "same branch, different outcome"


def test_records_the_iteration_ordinal():
    """PROV has no loop counter, so the ordinal is carried on the event.

    Without it, two passes through a loop differ only by list position, which
    is the defect this module exists to fix.
    """
    def work():
        total = 0
        for i in range(3):
            total += i
        return total

    ordinals = sorted({e["iteration"] for e in trace(work) if e.get("iteration") is not None})
    assert ordinals == [0, 1, 2], ordinals

Acceptance¶

  • [ ] Events carry expression-level spans on source the tracer did not compile.
  • [ ] No lineno * 1000 + col_offset packing anywhere.
  • [ ] C callees appear with their fully qualified name.
  • [ ] index is a total order over events, so ordering never depends on list position alone.
  • [ ] Every event validates against trace-event.schema.json.
  • [ ] tests/test_trace.py imports only awl.trace and awl.contracts.

Known limits¶

  • Overhead is large. f_trace_opcodes fires per instruction, and this is not the mechanism for production runs; sys.monitoring with only BRANCH and CALL enabled is.
  • Only one trace function and one profile function can be installed per thread, so this conflicts with debuggers, coverage and profilers. Say so in the docstring rather than trying to chain them.
  • Threads need threading.settrace separately; not handled here.
  • coverage.py was evaluated for this and rejected, because CoverageData does not store the called lines in order. Recorded so nobody re-evaluates it.
